# Phase 2 research - Requiem and its LoreRim patches versus dialogue, quests and speech checks

Scope: LoreRim (MO2 profile `Ultra`, 3,949 enabled mods, 3,495 active plugins), Requiem 5.4.5 + LoreRim's Reqtificator output, CHIM 3.3.2. Everything below was produced READ-ONLY.
Conventions: **[V]** verified in a source I opened (file:line, URL, or the scan JSON). **[I]** inference / design reasoning. **NOT FOUND** = searched, nothing found (locations stated).
Artifacts next to this file: `p2_dialogue_overrides.py` (the scanner, runs in WSL in ~55 s) and `p2_dialogue_overrides.json` (2.2 MB, all numbers below come from it; 0 parse errors, 0 missing plugins, master-first reorder changed 0 positions).
Caveat on web sources: fetched through a relay model; enum values were cross-checked against the scan (e.g. ActorValue 17 = Speechcraft is self-verified: every `GetActorValue(17)` comparand is a `Speech*` global).

## Executive summary (what changes the build)

1. **Requiem itself barely touches dialogue.** `Requiem.esp` overrides 29 vanilla DIAL / 46 vanilla INFO, adds 9 INFO + 1 top-level branch, touches **zero** speech-check INFOs. `Requiem for the Indifferent.esp` (79 MB) contains **no DIAL / INFO / QUST at all** - only GLOB, WEAP, NPC_, LVLN, LVLI, FLST. Requiem's effect on persuade / intimidate / bribe is entirely in **game settings, perks and NPC stats** - all of which only the engine's real formulas see. This is the strongest possible confirmation of the decided mechanism (real headless session): anything the glue would compute itself would be wrong under Requiem.
2. **Never hardcode speech numbers.** Bribe GMSTs are rewritten (fBribeCostCurve 1.4 -> 1.0, fBribeScale 0.5 -> 1.0, fBribeSpeechcraftMult 0.1 -> 1.0, + fBribeBase 100, fBribeMoralityMult 0.3, fBribeNPCLevelMult 1.0); the vanilla Persuasion / Intimidation / Bribery perks are **nulled** and folded into "Silver Tongue" (Mod Player Intimidation x3.0 + PerksQuest stage 60); six other perks from LoreRim mods multiply intimidation (x0.1 ... x3.0); the five `Speech*` globals are vanilla in the plugins (10/25/50/75/100) but are **re-rolled at runtime by script** (Speechcraft Randomization) when Silver Tongue is taken. Any pass/fail "prediction" shown to the LLM must be read from the live game (`GlobalVariable.GetValue`, `Actor.GetBribeAmount`, `PO3 EvaluateConditionList`) and labelled a hint.
3. **Speech-check identity cannot come from the "(Persuade)" text tag.** In the winning load order there are 403 speech-check topics; 156 of them have INFO-level prompt overrides (RNAM - Immersive Speech Dialogues, LoreRim - Dialogue Patch, More To Say ...) where the success INFO and the failure INFO show *different player lines* and the success line often has no tag. The menu shows the RNAM of the INFO the engine has *already selected* **[I - inferred from UESP's RNAM semantics + `MenuTopicManager::Dialogue::parentTopicInfo`; experiment E-R3]** - so the list text itself encodes pass/fail, but only an offline index (prompt text -> topic / kind / pass-or-fail INFO) can decode it on the Papyrus-only route. The scanner already emits that index (`speech_topics_winning_state`).
4. **The real Dialogue Menu open/close events are load-bearing in LoreRim**: `Beneficial Speech Checks` grants its rewards by diffing the `Persuasions` / `Intimidations` game stats between `OnMenuOpen("Dialogue Menu")` and `OnMenuClose`. Requiem's `REQ_TrainingSessions` keys on `"Training Menu"`. A hidden-but-real session keeps both working; any no-menu path would silently break them. Consequence: one hidden session per conversation turn that contains a check, close it cleanly, never keep one session open across many checks.
5. **What bypasses Requiem is not the headless session - it is CHIM's own action layer**: `ForgiveCrime` (`SetCrimeGold(0)`), `OpenInventory` -> `ShowBarterMenu()` on any NPC, ScriptProxy `SetBribed` / `SetIntimidated` / `SetCrimeGold`, and the (currently OFF) CHIM quest engine whose beats `set_stage` on the keyword "persuade". These must be disabled or re-routed through real topics while the glue is active.
6. **Crime / arrest dialogue is the one place where the watchdog must never "cancel"**: guard arrest INFOs carry the Walk-Away flag (0x0080); closing the session = resisting arrest, which under Requiem is usually death. On any failure in a crime session: un-hide the vanilla menu, do not close it.

## 2. Data from the active load order (`p2_dialogue_overrides.json`)

## 3. What a headless REAL session gets right for free under Requiem - and what it does not

### 3.1 Free (engine does it; zero glue code, zero per-mod data)
1. **Winning conditions, winning order, winning fragments.** Every change in section 2(a) - extra level / skill / race gates (Minor Arcana, LoreRim patch), removed checks (RisingAtDawn), disabled topics (`TRUEGlobal == 0`), swapped factions (CFTO), USSEP run-on fixes, 621 injected INFOs that change "first passing INFO" - is just CTDA data the engine evaluates with full quest / alias context.

5. **Requiem's quest / economy edits** (Nazir payouts in gems, lumber price, house prices, trainer caps, disabled "cut lumber" INFOs, Hogithum hand-in) run as the winning fragments / conditions.
6. **Reqtificator is irrelevant to dialogue structure** (no DIAL / INFO / QUST) - no re-scan is needed after the owner re-runs it, except for NPC stats which the engine reads live anyway.

### 3.3 Answers to the owner's sentence
- *"fully compatible with Requiem"*: yes by construction - Requiem's speech changes are settings + perks + NPC stats, all consumed only by the engine functions the real INFO conditions call. The glue adds zero formulas.
- *"changes in quest and dialogue as well, same with LoreRim"*: 8,818 overridden vanilla INFOs and 77,452 new ones are handled generically because the engine reads the winning records; the only per-load-order data the glue wants is the generated prompt index (R4), which is read-only and regenerable.
- *"branching choices"*: 18,805 INFOs with TCLT links, 4,482 invisible-continues, 3,734 RNAM overrides - all engine-resolved; the handler must re-read the list after every response and must accept RNAM text (not topic FULL) as the visible label.
- *"persuade, intimidate, bribe ... and the LLM"*: the engine picks success / failure; the LLM chooses WHICH option matches the player's words (using the index to know an option is a check, its kind, and - when RNAMs differ - its already-decided outcome) and narrates only after the response INFO is known. CHIM-native shortcuts that fake these outcomes are switched off (R1, R2).
