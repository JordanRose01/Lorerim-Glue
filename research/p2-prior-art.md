### 0.2 Who releases the held click today [V-local]
- CHIM's Papyrus still contains the DBVO-style release `UI.InvokeString("Dialogue Menu", "_root.DialogueMenu_mc.startTopicClickedTimer", "off")` (`CHIM\Source\Scripts\AIAgentPapyrusFunctions.psc:1174, 1182, 1193`) but the listener is switched OFF at init: `thirdPartyInit()` runs `UnRegisterForModEvent("PlayMenuTopic")` with the comment "Traditional dialogue Player TTS is handled in native code. Re-registering the Papyrus bridge here can resume the held topic twice." (:1097-1100). CHIM's authors already hit the double-release bug.
- AIAgent.dll strings: `_root.DialogueMenu_mc.startTopicClickedTimer`, `QueuePlayerMenuTopicTimerOff`, `PlayMenuTopic`, `TopicClicked`, "[PlayerMenuTTS] Releasing held topic for '{}' ({})", "[PlayerMenuTTS] Released dialogue gate due to timeout", "[PlayerMenuTTS] Timed out waiting for selected dialogue topic; replaying original click", "[PlayerMenuTTS] NPC dialogue advanced before delayed topic capture completed; clearing state", "[PlayerMenuTTS] Mod callback event source unavailable; native dialogue menu fallback disabled", "[HTTPManager] Released dialogue menu after stream timeout without a response for {}". So the DLL (a) answers `PlayMenuTopic` and releases through the same Scaleform function, with its own timeout, and (b) has a second, native click-delay/replay mechanism. Exact behaviour with the setting off: closed source, NOT VERIFIED.

### 0.3 Norden UI's SWF (what you fall back to if CHIM's SWF ever loses the conflict) [V-local]
Same SE class family and same member names (`DialogueMenu`, `TopicListHolder.List_mc`, `EntriesA`, `iHighlightedIndex`, `SetSelectedTopic` SE variant, `SetSelectedIndexByMouse`, labels `topicClicked/fadeListIn/slideListIn`), but `onSelectionClick` calls `GameDelegate.call("TopicClicked", [TopicList.selectedEntry.topicIndex])` directly; there is NO `startTopicClickedTimer`, `timerBool`, `initMenu` or `SendModEvent`. It is a Dear Diary Dark Mode / Convenient-Dialogue-UI lineage file: it loads `deardiary_dm/config.txt` through `LoadVars` (keys `bHideName`, `bHideExitButton`, `bHideNumbers`, `bHideTopics`, `fTopicsXOffset`, ...), and with `HIDE_TOPICS == 'true'` it calls its own `topicsFadeOut()` right after the click - i.e. a UI replacer that already hides the topic list while the NPC answers, inside the SWF. Same `onSelectionClick(abMouseClick)` -> `SetSelectedIndexByMouse(false)` trap as CHIM's.

### 0.4 What this changes [V facts, I design]
1. `_root.DialogueMenu_mc` is the right root on the installed SWF (CHIM ships Papyrus that uses it; Smart Talk's INI and Predictable Persuasion use the same root - section 2.1). DSN's `_level0.` is the same object addressed from C++.
2. On CHIM's SWF `onSelectionClick` never reaches the engine by itself. Pick exactly ONE release path per click, or the engine gets `TopicClicked` twice:
   - **Path A - universal (works on CHIM's AND Norden's SWF):** `TopicList.SetSelectedTopic(topicIndex)` then `UI.Invoke("Dialogue Menu", "_root.DialogueMenu_mc.onSelectionClick")` with NO argument. On a vanilla-family SWF this clicks immediately; on CHIM's SWF it fires `PlayMenuTopic` and AIAgent.dll releases (at once when `_player_tts_traditional_dialogue` <= 0 per the Papyrus twin of that handler, after player TTS otherwise). This is literally what a human click does. Watchdog: `UI.GetBool("Dialogue Menu", "_root.DialogueMenu_mc.timerBool")` still true after N ms => the gate is stuck => release it ourselves with `startTopicClickedTimer("off")` (safe, because `timerBool` true proves nobody released yet).
   - **Path B - CHIM-SWF only, no CHIM involvement:** `SetSelectedTopic(topicIndex)` then `UI.InvokeString("Dialogue Menu", "_root.DialogueMenu_mc.startTopicClickedTimer", "off")` - the exact call CHIM ships. No mod event, no player-TTS of the prompt, no dependency on AIAgent.dll timing. On Norden's SWF it is a silent no-op (function absent), so it needs the SWF-family probe. Side effect: `eMenuState` is not advanced to `TOPIC_CLICKED`, so the next `DoShowDialogueList` does not run `ShowDialogueList`; entries are still replaced by `PopulateDialogueLists`, so list reading keeps working, but `eMenuState` stops tracking the engine unless the glue writes it (`UI.SetInt`, `UI.psc:58`).
   - SWF-family probe [I]: after Path A's `onSelectionClick`, `timerBool == true` means DBVO/CHIM family (gate holding); never true on Norden/vanilla.
3. NEVER pass a truthy argument to `onSelectionClick` on SE-family SWFs: it means "this was a mouse click" and re-selects the entry under the (hidden) cursor. DSN passes `"%d", 1.0`; that is a C varargs type mismatch that most likely arrives as 0 [I], so it got away with it. (Answers dialogue-engine.md E5: the argument is not needed and is harmful.)
4. Select with `SetSelectedTopic(topicIndex)`, not with `doSetSelectedIndex(position)`: it takes the engine's own `topicIndex` (the value `TopicClicked` sends back), is scroll-independent (long lists), and survives the controller rule in `UpdateList` (selection := scroll centre). Always carry each entry's `topicIndex`; never assume position == topicIndex.
5. A hidden menu still receives input: `onMouseDown` -> `onItemSelect` -> `onSelectionClick(true)`. A stray click / E press while the list is invisible selects a topic. Papyrus-only guard idea [I]: once the list is ready, PARK the state machine: `UI.SetInt(... "_root.DialogueMenu_mc.eMenuState", 3)` (TRANSITIONING). In state 3 `onItemSelect` does nothing, up/down is ignored by `handleInput`, Tab still closes the session (walk-away stays the player's right). With Path B the glue's click does not depend on `eMenuState`, and because `DoShowDialogueList` only animates from state 2 or 0, the parked state persists across layers. Un-park (state 1, holder back on screen, `bAllowProgress = true`) = the emergency "show the vanilla menu" hotkey.
6. Hide the LIST, not the whole menu [I]: `DialogueMenu_mc._visible = false` also hides `SubtitleText` and `SpeakerName` (NPC subtitles during dialogue are drawn by this movie via `ShowDialogueText`), and `ShowDialogueList` sets `TopicListHolder._visible = true` again on every layer. Moving the holder off-screen (`UI.SetFloat(... "_root.DialogueMenu_mc.TopicListHolder._x", -5000)`; nothing in the class writes `_x` on the holder) persists across layers, keeps subtitles, and takes the entries out from under the cursor (`Mouse.getTopMostEntity()`), which also defuses `SetSelectedIndexByMouse`. `ExitButton._visible` is re-written by every `DoShowDialogueList`; move it off-screen too. SKSE's own `UI.psc:54` documents `UI.SetBool("InventoryMenu", "_root.Menu_mc._visible", false)` as the canonical hide example. The movie is re-created on every menu open, so hide again on every `OnMenuOpen`; a 1-2 frame flash before Papyrus reacts is unavoidable without a DLL.
7. "List ready" is a state, not a delay: clickable when `eMenuState == 1`, which the timeline sets 0.33-0.47 s after the engine's `ShowDialogueList`. Flash timelines keep running while a clip is invisible/off-screen [I - standard Flash behaviour; confirm in game].

### 1.1 Dragonborn Speaks Naturally (DSN) - voice selects vanilla topics, menu open
Sources [V]: https://raw.githubusercontent.com/YihaoPeng/DragonbornSpeaksNaturally/master/dsn_plugin/dsn_plugin/Hooks.cpp , `.../SpeechRecognitionClient.cpp`, `.../ReversingNotes.txt`, `.../DragonbornSpeaksNaturally.SAMPLE.ini`, `dsn_service/dsn_service/DialogueList.cs`, `Phrases.cs`; issues of YihaoPeng/ and DougHamil/DragonbornSpeaksNaturally.
- Reading the list: hooks the engine->Scaleform `Invoke` (`Hook_Invoke(GFxMovieView* movie, char* gfxMethod, GFxValue* argv, UInt32 argc)`, "InvokeFunction + 0xEE ... 0xE5 in AE"). On `"PopulateDialogueList"`: `numTopics = (argc - 2) / 3; for (j = 1; j < argc - 1; j += 3) lines.push_back(argv[j])` - i.e. the prompts are the engine's own args (text / isNew / topicIndex triples). It caches the movie pointer.
- List identity: `StartDialogue(list)` returns early when the list equals the current one (the engine re-sends identical lists), else `currentDialogueId++` and sends `START_DIALOGUE|<id>|line|line...`; an answer `DIALOGUE|<id>|<index>` is accepted only `if (dialogueId == this->currentDialogueId)`. Stale recognitions are dropped.
- Selecting (game-loop hook): reads `_level0.DialogueMenu_mc.eMenuState`; `if (menuState == 2) // NPC Responding` -> stop listening and forget the movie. To click: if `TopicList.iSelectedIndex` != wanted -> `TopicList.SetSelectedTopic(i)`, `TopicList.doSetSelectedIndex(i)`, `TopicList.UpdateList()`; then `DialogueMenu_mc.onSelectionClick`. Goodbye phrases map to index -2 -> `_level0.DialogueMenu_mc.StartHideMenu` (engine-clean close).
- Matching: `dialogueMinConfidence=0.5`, `goodbyePhrases=...`, `SubsetMatchingMode=None` with the warning that enabling it "can greatly increase the probability of false matches"; phrases are normalised by configurable regex; grammar creation failures for odd lines are caught and logged.
- Failure modes reported: (1) use-after-free of the cached movie: issue #11 "SSE crash when teleport with a dialogue line" - "a teleport was triggered before the dialogue menu was closed, so `dialogueMenu` became a ghost pointer" (go-to-jail, Dark Brotherhood door); issue #21 (0.31.1) same class: "the dialogueMenu object is recycled ... the solution is always get it rather than using cached global". (2) issue #1 "non-ASCII characters garbled between stdin/stdout" (localisation). (3) issue #14: silently "no responses" inside a big Wabbajack list (Animonculory), never diagnosed - nobody could tell which UI/SKSE mod broke it. Nexus comment threads: not readable (403).
- Lessons: list-generation id (= the glue's `gen`) is proven; de-duplicate identical re-populates; never cache anything across a menu close (SKSE's Papyrus `UI.*` looks the movie up per call, so the Papyrus route is immune to the ghost-pointer crash); sessions can end by TELEPORT with the menu still open (jail, scripted doors) - the watchdog must treat "menu closed / cell changed mid-layer" as normal; say-goodbye = `StartHideMenu`; silent failure in big lists means the glue needs a self-test that reports "list unreadable" loudly.

### 1.2 DBVO family - the click-gate pattern CHIM copied
Sources: DBVO 1.x `DialogueMenu.as` as redistributed at the myaiexp URL above [V]; `docs/dbvo-landscape.md` and `mods/DBVODialogueTweaks/README.md` in the same repo [V - third-party analysis]; Nexus snippets for DBVO 2 / ASP patcher [V-snippet].
- Technique (1.x): patched SWF holds the click (`onSelectionClick` -> `skse.SendModEvent("PlayDBVOTopic", sanitisedText)`), Papyrus plays the player line (`ConsoleUtil` `Player.SpeakSound`), then `UI.InvokeString(... startTopicClickedTimer ...)`; the SWF waits `words x 200 + 1400 ms` and only then sends `TopicClicked`. DBVO 2 / DBReV moved to an SKSE DLL with no SWF ("does not require any patched dialoguemenu.swf").
- Failure modes: (1) word-count timing - "dead air on faster AI voices ... or overlap on slower ones". (2) Every UI overhaul needs its own patched SWF; users who let the wrong SWF win saw the menu move ("dialogue options moved from left to right"). (3) "Every patched SWF removed stock DBVO's `this.timerBool = false;` from the voice-off branch ... causes topic list to hang when voice is disabled" - with `timerBool` stuck true, `DoShowDialogueList` is ignored forever. (4) Smart Talk bug report #87 (2026-09-04, Smart Talk 1.0.6 on 1.6.1170): skipping right after a click, "NPC stop speaking the current line, but also not proceeding to the next one ... Click again; NPC may repeat original line", suspected interaction with the held DBVO click (https://github.com/Seb263/SkyrimSE_ModBugReports/issues/87). (5) An `Invoke` on a function the SWF lacks "is a silent no-op".
- Lessons: the gate's single point of failure is `timerBool`; the glue must watch it and must never leave it true. Calls into a SWF that lacks the function fail silently, so every capability needs a positive probe. Do not combine "skip" with a held click.

### 1.3 Mantella - awareness only
Sources [V]: https://github.com/mikastamm/mantella-vanilla-dialogue (README, `plugin.cpp` on `master`), `Mantella-Spell/Scripts/Source/MantellaVanillaDialogue.psc` (four natives: `notifyConversationStart/End`, `notifyNpcAdded/Removed`), `MantellaDialogueItems.psc` (a TopicInfo fragment that starts/extends a Mantella conversation from a vanilla topic), issue #628.
- Technique: SKSE hooks on the two subtitle call sites (`RELOCATION_ID(19119,19521)+0x2B2`, `(36543,37544)+0x8EC/0x8C2`), reads `MenuTopicManager::lastSelectedDialogue->topicText` plus all `responses[*]->text`: "As soon as a dialogue item is selected by the player, all the sentences get sent to Mantella that the NPC will say in response." De-dupes by last player topic text; filters short replies and non-unique greetings (SayOnce flag).
- Known issues (README): "Vanilla dialogue attached to failed responses never reaches Mantella"; queue culling; stored lines lost if a conversation ends without a summary.
- Mantella never selects topics. Issue #628 (2025-12-18, no replies) proposes `QuestX.SetStage(10)` on detected intent - no branching, no speech checks, exactly the anti-pattern the glue rejected.
- Lessons: pushing the WHOLE response text to the LLM at click time is practical natively (CHIM's DLL already logs player and NPC lines, chim-dll-esp.md:368); greeting spam must be filtered out of LLM context; nothing to copy for selection.

### 1.4 Predictable Persuasion - speech checks as data
Sources [V]: https://raw.githubusercontent.com/JonathanFeenstra/PredictablePersuasion/main/src/Hooks.cpp , `src/Scaleform.cpp`, `config/PredictablePersuasion.ini`.
- Technique: vfunc 0x4 (`ProcessMessage`) of `DialogueMenu` on kShow/kUpdate/kHide; walks `dialogueList`; classifies by conditions (`kGetActorValue`+`kSpeech`+`>=` = persuade, often OR-ed with `kGetEquipped` Amulet of Articulation; `kGetBribeSuccess`; `kGetIntimidateSuccess`); evaluates ONLY that condition with `ConditionCheckParams(speaker, player)`. Scaleform side uses `_root.DialogueMenu_mc.TopicListHolder.List_mc`, member `EntriesA`, `iHighlightedIndex` ("to support mods that decouple mouse highlighting from selection"), fallback `Invoke("__get__selectedEntry")`, `_root.DialogueMenu_mc.SubtitleText`; wraps `SetEntryText`, `doSetSelectedIndex`, `moveSelectionUp/Down`.
- Failure modes it documents: "evaluating the full responseInfo->objConditions sometimes returns false negatives, so only the speech checks are evaluated here"; tags are text and language-dependent - INI `sPersuadeTagRegex = " \((Persuade)\)$"`, `sIntimidateTagRegex = " \((Intimidate)\)$"`, `sBribeTagRegex = " \((\d+ gold)\)$"` with "Do not change these unless you use a different game language ... or a mod that changes these tags"; a `sNoCheckText = "No Check"` class exists because some topics carry the tag with no real check; "{4} predictedResponseText ... May not always be available or accurate"; "besides the speech check, additional checks may be applied which are not accounted for in the result".
- Lessons: (1) the bribe regex proves `<BribeCost>` is already substituted with the number in the list text the glue will read. (2) Papyrus-only tag detection must be a configurable, per-language regex, and a tag does not prove a check. (3) Prediction is unreliable even natively - the glue's rule "the LLM never sees or sets the outcome; the engine decides" is the right one. (4) That a native plugin needed a fallback for `selectedEntry` is a warning that getter properties may not resolve everywhere - test both `EntriesA.N.text` and `selectedEntry.text` from Papyrus.

### 1.5 Installed LoreRim mods that already touch speech checks [V-local] (prior art AND compatibility facts)

- Lessons: (1) thresholds in LoreRim are live globals that change after every success - any cached or offline prediction is wrong; only the engine's evaluation at click time is right (supports the decided mechanism). Caveat [I]: only INFOs whose success fragment calls `FavorDialogueScript` move those stats. (3) These mods depend on the real Dialogue Menu opening and closing; a hidden real session keeps them working, a blocked menu would break them.

### 1.6 Smart Talk 1.0.5 (installed) - the other thing hooked into the same menu
Sources: `F:\Modlists\LoreRim\mods\Smart Talk (Dialogue Menu Enhancer)\SKSE\Plugins\SmartTalk.ini` [V-local]; source is public (GPL-3.0): https://github.com/Seb263/SkyrimSE_SmartTalk (`src/Features/Sorting.hpp`, `Input.hpp`) [V].

### 1.7 Skyrim Souls RE - proof that a hidden Dialogue Menu keeps its session
Source [V]: https://raw.githubusercontent.com/Vermunds/SkyrimSoulsRE/master/src/Menus/DialogueMenuEx.cpp . ### 2.2 Timing rules
1. List available: after the engine's `PopulateDialogueList`; clickable when `eMenuState == 1` (0.33 s fade / 0.47 s slide after `ShowDialogueList` at 30 fps). DSN starts on `PopulateDialogueList`, stops at state 2.
2. First greeting: state 0 until the first non-empty list is shown; during state 0 cancel/E only skips the greeting line; the list may arrive while the greeting is still playing (vanilla allows clicking then).
3. After a click: state 2 immediately (Path A) and again at frame 21; while `timerBool` is true the next list cannot be shown. Next layer = state returns to 1 with a changed entry signature, or the menu closes (Goodbye), or the cell changes (teleport INFOs).
4. Papyrus: `UI.Get*/Set*` synchronous, `UI.Invoke*` queued FIFO - never read-after-invoke without a `WaitMenuMode` tick; re-read the list immediately before clicking and verify `topicIndex` + text.
5. Identical lists are re-sent by the engine (DSN de-dupes) - do not bump `gen` on an identical signature.
6. Skips: not before 500 ms into a response with a fragment (Smart Talk `iPapyrusHandle=3`), never while a click is held.
7. CHIM's gate has its own timeout/replay; with Path A allow for it before the glue's watchdog fires, and only self-release when `timerBool` is still true.
8. Invoke on a missing function is silent - every step needs an observable post-condition (state change, `timerBool`, list signature change, `IsInDialogueWithPlayer`, menu close) and a timeout to the un-hide fallback.

### 2.3 Things every project got burned by
- **UI replacers / SWF conflicts:** DBVO needed a patched SWF per UI mod and third-party patches broke `timerBool`; DSN died silently in a big list; BDC/EZ2C/number-key mods all demand to win the conflict. Glue: probe, do not assume; support both SWF families (Path A universal, Path B CHIM-only); loud self-test.
- **Localisation:** DSN garbled non-ASCII; PP's tag regexes are English-only by default. Glue: never parse meaning out of tags without a per-language regex; send prompts to the LLM verbatim as UTF-8; match by `topicIndex`, never by text alone. Papyrus strings are case-insensitively interned, so text comparisons must be case-insensitive [I - general Papyrus behaviour, not re-verified here].
- **Controller vs keyboard selection paths:** `UpdateList` snaps selection to the scroll centre when `iPlatform != 0`; mouse hover/click re-selects by cursor. Glue: `SetSelectedTopic(topicIndex)` only; never a truthy `onSelectionClick` argument; move the list off-screen.
- **List re-ordering:** Smart Talk can re-sort the engine list; the engine re-populates at will. Glue: no cached positions; `gen` + `topicIndex` + text check at click time; stale -> reject and re-enumerate (already design item 9/11).
- **Topics with empty text:** SWF prints `" "`; DSN's grammar builder throws on odd lines. Glue: keep the entry (it has a `topicIndex`); auto-select when it is the only entry, otherwise label it "(continue)" for the LLM.
- **Very long lists / scrolling:** all entries live in `EntriesA` regardless of what is drawn; `SetSelectedTopic` is scroll-independent; centred list max scroll = count - 1, so no clamp surprise. Cap what the LLM sees, not what the glue can click.
- **The first greeting:** state 0 semantics differ (cancel = skip, not close); ForceGreet INFOs carry fragments, and skipping them early can stop the fragment (Smart Talk's warning).
- **Walk-away / teleport / close:** DSN crashed on sessions that ended by teleport; close through `StartHideMenu` (engine `CloseMenu`), never by killing dialogue; treat unexpected menu close as a normal end of session.
- **Held-click gates:** double release (CHIM's own comment), stuck `timerBool` (DBVO patches), skip-while-held freeze (Smart Talk #87).
- **Prediction:** PP admits false negatives and inaccurate predicted responses; LoreRim re-rolls thresholds. Let the engine decide; detect outcomes after the fact (stats / gold / bribed / intimidated).
- **Re-implementing quest effects:** every AI project that touched quests did `SetStage` by hand (CHIM beta, Mantella #628) and none covers mod quests; nobody has shipped engine-driven topic selection by an LLM. The decided mechanism is new ground, and DSN is its closest working ancestor.
