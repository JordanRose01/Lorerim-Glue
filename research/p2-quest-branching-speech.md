## 0. What changes the design (read this first)

1. **Text tags alone are NOT a reliable speech-check detector in this load order.** `Immersive Speech Dialogues.esp`, `LoreRim - Dialogue Patch.esp` and `Narrative Gameplay Consistent Dialogue Tweaks.esp` rewrite the prompts: of 237 persuade topics 18 show no tag in either variant ("hidden checks"; 11 of them do not even call FavorDialogueScript - `Poetic Duels.esp`, `TomeTrials.esp`, FDE followers, CC Altar) and 24 more show it in only one variant; 12 of 84 intimidate topics are partly or fully untagged [V `json:deep.speech_topics`; the looser `json:speech_crosstab` count "persuade tag=0 cond=1 = 40" also includes non-check uses of Speechcraft such as the trainer cap `GetBaseActorValue Speechcraft < 90`]. Bribes are the exception: all 62 real bribe topics carry `(<BribeCost> gold)`.
2. **The menu text already tells the outcome for a third of the checks.** The engine picks the INFO when it builds the list and shows THAT INFO's prompt (RNAM). Immersive Speech Dialogues gives the success INFO and the failure INFO different prompts: 76/237 persuade, 37/84 intimidate, 10/62 bribe topics [V]. An offline index of prompt text therefore knows "this entry is the FAILURE variant" before the click.
3. **Build an offline PROMPT INDEX (data-driven, no plugin edits, no DLL).** The scanner in this folder already produces it: prompt text -> topic, quest, speech-check kind and variant, INFO flags (Goodbye / Invisible Continue / Walk Away / Say Once), "has script fragment", link fan-out, first NPC response text. Text-only matching is good enough: 93.1 % of 21,878 distinct prompts belong to exactly one topic and 99.1 % of 4,764 multi-entry layer "fingerprints" belong to exactly one quest [V `json:deep.prompt_uniqueness`, `json:deep.layer_fingerprints`]. This recovers most of what the DLL route would have given (identity, quest ownership, irreversibility hints).
4. **Do NOT blanket auto-advance single-entry layers** (amends REVIEW_40 item 7). 4,075 visible single-entry layers exist; in 1,324 (32 %) the single entry runs a script fragment and in 689 (17 %) it is script + Goodbye, i.e. "commit and close" (example: Blood on the Ice - the single entry after "I believe the killer is Wuunferth" jails him) [V `json:deep.single_entry_layers`]. Auto-advance only what the index marks unscripted (or continuer-like text); everything else waits for the player.
5. **Word heuristics for "real choice" are weak**: against the ground truth ">= 2 entries in the layer run a script" (2,154 layers) the choice-word list has 50 % recall and fires falsely on 28 % of pure conversation hubs [V `json:deep.multi_entry_layers`]. Index first, words only as the fallback for unindexed text.
6. **Outcome detection is cheap and already proven in this load order.** `Beneficial Speech Checks.esp` (installed, active) detects passed checks with `RegisterForMenu("Dialogue Menu")` + `Game.QueryStat("Persuasions"/"Intimidations")` deltas between menu open and close [V]. Add `Actor.IsBribed()`, `Actor.IsIntimidated()`, gold delta == `GetBribeAmount()`, and - the generic one - match the NPC's real line against the index's success / failure response text.
7. **SKSE has `bool Actor.WillIntimidateSucceed()`** [V `Actor.psc:704`] and `int Actor.GetBribeAmount()` [V `:175`]: Papyrus can pre-compute intimidate and bribe results exactly; persuade = player Speech vs the LIVE value of the global (never the constants 10/25/50/75/100 - `Speechcraft Randomization` is installed and re-rolls them).
8. **FavorDialogueScript's real body is now on disk** (closes E11): gold removal is inside `Bribe()` and is guarded by an affordability check; `Persuade/Bribe/Intimidate` increment the stats "Persuasions" / "Bribes" / "Intimidations" [V].
9. **Skyrim scenes have no "player dialogue" action.** All 30,938 scene actions in the load order are Dialogue (23,695) / Package (5,875) / Timer (1,368) [V `json:scene_action_types`; UESP SCEN page]. In-scene choices are ForceGreet packages / blocking branches, i.e. ordinary engine-opened sessions. REVIEW_40 item 15 wording should be corrected, and "NPC in a scene -> stand down completely" needs the exception "unless the engine itself opened the Dialogue Menu".
10. **Service double handling: the real topic must win over CHIM's `RentRoom` / `HireCarriage` / `HireFerry` / `Brawl` / `TakeGoldFromPlayer`.** CHIM's versions re-implement the effect (fixed configured cost, direct `Game.FastTravel`, pokes `RentRoomScript` internals) and bypass what LoreRim changed (`Xtended Stay.esp` and `LoreRim - Dialogue Patch.esp` own the rent-room INFOs; `CFTO.esp` owns 72 carriage prompts) [V].
11. **Failing a check is not harmless**: a failure INFO runs a script in 68/237 persuade, 32/84 intimidate, 15/62 bribe topics and ends the conversation (Goodbye) in 70 / 41 / 1 [V `json:deep.speech_failure_shape`]. The "did the player really attempt it" judge must be conservative, and doomed retries must be suppressed by the glue (vanilla offers the same entry again immediately in 61 / 19 / 31 topics).
12. **Requiem / LoreRim touch speech checks only through data the engine reads anyway**: bribe GMSTs (`fBribeCostCurve` 1.4 -> 1.0, `fBribeScale` 0.5 -> 1.0, `fBribeSpeechcraftMult` 0.1 -> 1.0, won by `LoreRim - Economy Overhaul.esp` with Requiem's values) and perks. Requiem.esp's own dialogue footprint is 30 DIAL / 55 INFO, none of them speech checks [V]. Under the headless real session nothing extra is needed - but every number the glue shows the LLM must be read live (menu text, `GetBribeAmount()`), never computed.

Immersive Speech Dialogues' own description (Nexus 42090, stored in `mods\Immersive Speech Dialogues\meta.ini`) [V]: "Success and failure speech dialogue options are now differentiated". Example from the data: `MG03CallerBookPersuade` - success INFO prompt "There's been enough bloodshed. No need for more, if I can leave with the books." (condition Speech >= global 0D16A5), failure INFO prompt "I'm not going anywhere without those books."; the tagged FULL "... (Persuade)" is never displayed because every INFO has its own RNAM. That the engine shows the prompt of the INFO it selected at list-build time is confirmed by this mod's working principle and by Predictable Persuasion evaluating per-entry conditions at `ProcessMessage` time (https://raw.githubusercontent.com/JonathanFeenstra/PredictablePersuasion/main/src/Hooks.cpp) [V].
Conclusion: regex on the entry text finds ~85 % of real checks, mislabels ~70 tag-only entries as checks (harmless: they just always succeed) and cannot see the fully untagged ones (18 persuade, 1 intimidate) nor which VARIANT is on screen. With the prompt index the classification is exact for every indexed plugin.

Hidden checks matter less than it sounds: an untagged entry with a Speech condition (e.g. `MS09ThoraldQuestionsBranchTopic` "What do you know about Thorald Gray-Mane?", Speech >= SpeechHard for Idolaf) is just a question - clicking it is an ordinary topic selection and needs no "attempt" judgement.

### 2.3 How the bribe cost is rendered
- In the plugin: `(<BribeCost> gold)` - case varies (`<bribecost>`, `<BribeCost>`, "Gold"), one topic has `(Bribe <BribeCost> gold.)` [V `json:bribe_prompt_forms`].
- In the menu: the token is already substituted with digits. Evidence: Predictable Persuasion matches the DISPLAYED `topicText` with the regex `" (\(\d+ gold\))$"` and has to look at the RAW `parentTopic->fullName` to find `<bribecost>` (Hooks.cpp / Settings.cpp, keys `sBribeTagRegex`, `sPersuadeTagRegex` = `" (\(Persuade\))$"`, `sIntimidateTagRegex`) [V]. So `UI.GetString(... entryList.N.text)` yields e.g. "Look, I'm willing to pay. (137 gold)" [I for the Papyrus read path - that is the other team's E6].
- Parse with `\((\d[\d,\.]*)\s+(gold|septims?)\)\s*\.?$` (case-insensitive). CAUTION: the same shape is produced by `<Global=...> gold` prices (243 topics) and literal prices (116). Disambiguate: (1) index says `<bribecost>`; or (2) no index hit: the number equals `speaker.GetBribeAmount()` [V Actor.psc:175]. Either way the LLM rule is identical ("this entry costs N gold"), only the wording differs (bribe vs purchase).
- Other runtime tokens arrive resolved too (players see "How about Riften?" not `<Alias=...>`) [I]; the index must therefore store token prompts as patterns (`<...>` -> `(.+?)`), 576 prompts.

### 2.4 Placeholder prompts
`(Invisible Continue)` 28, `(forcegreet)` 5, `(Invisible Walk Away)`, `(Forced Goodbye)`, FULL == EditorID (e.g. `DB02Captive1Intimidate`, the real text is in RNAM) [V `json:deep.fully_parenthesised_prompts`]. Normally the engine never lists them (they hang under Invisible-Continue INFOs). Rule: an entry whose whole text matches `^\((invisible|forcegreet|forced good ?bye|walk away|invisible walk away).*\)` or looks like an EditorID (`^[A-Za-z0-9_]+$`, no spaces, > 12 chars) is auto-selected if it is the only entry, hidden from the LLM otherwise.

## 3. What the engine does on click, and how the glue learns the outcome (task item 2)

### 3.1 Structure as found in the data [V dump, e.g. `DA01NelacarPersuade/Bribe/Intimidate`]
- One topic, success INFO first (condition `GetActorValue(Speechcraft) >= <global>` OR `GetEquipped TGAmuletOfArticulationList`; `GetBribeSuccess == 1`; `GetIntimidateSuccess == 1`), unconditioned failure INFO after it. First passing INFO wins.
- Success INFO: usually Invisible Continue into the payoff chain (26 / 8 / 11 topics) or Goodbye (89 / 32 / 16), and its fragment calls `FavorDialogueScript` (VMAD property seen on 163/237, 67/84, 56/62).
- Failure INFO: links back to the same option set in 61 / 19 / 31 topics (retry offered at once), ends the conversation in 70 / 41 / 1, runs a script in 68 / 32 / 15.
- Say Once is rare on checks (success 15 / 2 / 4, failure 7 / 0 / 0): vanilla has NO cooldown on quest speech checks; they are deterministic, so a retry gives the same answer until the player's state changes.
- Persuade thresholds are globals in 257 of 299 conditions (`SpeechVeryEasy` 000D16A3, `SpeechEasy` 000D16A4, `SpeechAverage` 000D16A5, `SpeechHard` 000D1953, `SpeechVeryHard` 000D1954 - FormIDs verified in Skyrim.esm), literals (15..80) in the rest [V `json:deep.persuade_thresholds`].
- No bribe-success INFO in the whole load order carries a separate gold condition (0 of 86) [V] -> `GetBribeSuccess` itself must include affordability [I]; untested (E15).

### 3.4 Result record and the feedback the LLM receives
Game -> server after every executed entry (one message, < 2 KB), proposed fields: `cid`, `npcRefId`, `entryText`, `kind` (none | persuade | intimidate | bribe | pay | brawl | action), `pre{speech, gold, bribeAmount, willIntimidate, stats[3], isBribed, isIntimidated}`, `post{...}`, `sessionClosed`, `nextLayer[]`. The server joins it with the `traditional_npc_speech` rows for that NPC after the click time and with the index, then writes ONE ground-truth context line (volatile slot, `prompt_bottom`) and logs it as a glue event:

- Persuade success: `[GAME RESULT] {player}'s persuasion WORKED. {npc} answered (real, voiced): "{line}". Treat the matter as settled in {player}'s favour; do not reopen it.`
- Persuade failure: `[GAME RESULT] {player}'s persuasion FAILED - {npc} was not convinced and answered: "{line}". {npc} will not change their mind unless something about {player} changes. Do not soften this.` (+ ` The conversation ended.` when `sessionClosed`)
- Intimidate success / failure: same pattern; failure adds `{npc} is not afraid of {player}.`
- Bribe success: `[GAME RESULT] {npc} accepted a bribe: exactly {N} gold left {player}'s purse (the game moved the gold). {npc} answered: "{line}".` Failure: `... refused the bribe; no gold changed hands.`
- When the clicked entry was the differentiated FAILURE variant (2.2): prepend `{player}'s words came out badly: "{canned prompt}".` - this explains in-fiction why a well-argued speech failed (low Speech skill = poor delivery) and keeps the NPC's canned reaction coherent.
- Quest echo (already promised in REVIEW_40 item 18): `[GAME RESULT] Quest updated: "{quest}" - {objective}`.
The LLM never receives thresholds, skill numbers or "you would have needed 75".

## 4. LLM role for speech checks (task item 3)

### 4.1 Order of operations - the vanilla line IS the answer
1. Player utterance arrives (`inputtext` / `inputtext_s`). A cheap **judge** call (`fast_request`, Fast connector) classifies it against the CURRENT list: `{intent: none | select | speech_attempt | offer_gold | leave, entry, amount, confidence, names_choice}`. The judge sees entry texts with the tag stripped and replaced by a label (`[persuasion attempt]`, `[threat]`, `[costs 137 gold]`, `[silent]`, `[action: give X]`).
2. `speech_attempt` accepted by the rules below -> the select command goes to the game; **the NPC says nothing generated this turn**. Enforcement: the prompt rule "when you call SelectTopic, your spoken text must be empty" plus the post-LLM gate `$GLOBALS["action_post_process_fnct_ex"][]` dropping any speech wire line that accompanies a SelectTopic of kind persuade / intimidate / bribe / irreversible [hook verified in server-lifecycle-actions.md; whether a request can be ended with NO speech line at all is an open server question, E17].
3. Engine picks the INFO, plays the real voiced line, runs the fragment. Glue sends the result record (3.4).
4. Grok speaks again only on the NEXT player utterance, with the `[GAME RESULT]` line in context. It can elaborate, never contradict.
Not attempted / not accepted -> ordinary CHIM conversation; the NPC may resist, haggle, scoff - but may not concede (4.2 rule A).

### 4.2 Decision rules

| # | Situation | Glue / LLM behaviour |
|---|---|---|
| A | Player tries to persuade / threaten / bribe, but **no matching entry is in the current list** | No click. Static prompt rule (`character_bottom`): "Nothing the player says can make you grant access, items, payment, secrets or quest help unless the game offers it; stay in character and deflect." If the entry exists in the index for this NPC but is not listed now (wrong layer / quest stage), the hint is "not now" rather than "never". If we are inside a closed layer, the entry may be on the top level: finish or leave the layer first. |
| B | Entry present, attempt **unambiguous** (persuade: gives a reason / appeal / claim aimed at exactly this matter; intimidate: explicit or clearly implied threat of harm or consequence aimed at the NPC; both: relevant to the entry's subject) | Click once. Voice input (`inputtext_s`) needs judge confidence "high"; typed input "medium". |
| C | Attempt **ambiguous** (polite request, a question, sarcasm, STT garble) | No click. NPC answers in character and invites the move ("If you have something to say, say it."). Failing costs something in 30-50 % of topics (3.1), so false positives are worse than false negatives. |
| D | **Bribe, amount named** A vs engine price N (N from the menu text, cross-checked with `GetBribeAmount()`) | A >= N and gold >= N -> click; feedback says exactly N moved. A < N -> no click; NPC haggles upward (config: reveal N, or only "more"). Never click on a lower offer - the engine would take N, not A. |
| E | **Bribe, no amount** ("maybe some coin would help?") | No click yet; the NPC names the price N (injected as a fact); the player must agree ("fine, 137") -> click. This is the two-step flow for free. |

## 5. Branching choices from the UI alone (task item 4)

### 5.1 What a layer is, operationally
- **Top-level list** = the first list after the greeting of a session the player (or the glue) opened on an ordinary NPC. Entries = starting topics of Top-Level branches of every running quest: a menu of things to raise. 7,702 top-level topics exist; 4,505 belong to a journal quest (type != 0 or has objectives - the same test Smart Talk uses, `SmartTalk.ini` `iLinkedQuestFilter = 3`), 3,197 to dialogue-only quests [V `json:deep.journal_quest_split`].
- **Closed layer** = any list that appears after a click in this session, or the FIRST list of an engine-opened session (ForceGreet / blocking branch: guards, MQ302, couriers). Only linked topics are listed; the player cannot reach other topics without answering or leaving.
- Fan-out of the 37,976 player INFOs: 0 links 22,293 (back to the previous list / end), 1 link 7,708, 2 links 3,480, 3 1,710, 4 1,212, 5 567, 6+ 1,006 [V `json:info_link_fanout`].

### 5.2 "This is a real choice" - detector stack (first hit wins)
1. **Index, layer fingerprint**: the set of entry texts identifies the parent INFO (99.1 % unique to a quest). `>= 2` entries whose INFOs have a script -> CHOICE (2,154 layers); `>= 2` with script + Goodbye -> IRREVERSIBLE candidate (951). Entry flagged META (`(skip quest)` etc.), `(attack)`, `(brawl)`, `(remain silent)` with script, relationship switches -> irreversible-class regardless of siblings.
2. **Index, single entry**: scripted + Goodbye single entry (689) -> COMMIT (5.4).
3. **UI-only fallback** (text not in the index: new mod, stale index): closed layer AND >= 2 entries AND (the NPC's last real line ends with "?" or contains "choose / decide / which / will you / what say you", OR any entry matches the choice-word list: kill, spare, join, side with, accept, refuse, give, keep, let ... go, free, arrest, betray, lie, promise, marry, attack, pay, surrender, "I'll do it", "count me in/out", yes / no). Measured quality of the word list alone: recall 50 %, false alarm 28 % -> in fallback mode every closed layer with >= 2 entries where ALL entries are `topicIsNew` is treated as a choice needing explicit naming (cheap: the player just has to say which one).
4. `topicIsNew` helps the other way round: an entry that is NOT new in a closed layer has been said before, so it is not a one-shot commit -> safe to select on medium confidence.
- **Back-out entries** (1,069 layers have one): "Never mind.", "I need more time", "Forget I asked", "I'll come back later", "I misspoke", "Let's talk about something else.", "Actually, I'm not sure yet..." -> the safe exit; never treated as a choice.

### 5.3 Two-step confirmation
State machine per session: `LISTED -> (judge: names an irreversible entry) PARKED -> NPC_ASKED -> (separate affirmative utterance naming the choice) EXECUTE`, with `PARKED` expiring after 60 s or on any unrelated utterance.
- The NPC "ask" is normally already there: the vanilla line that opened the layer ("So, who is it?", "What do you think Markarth is worth?", "What say you in your defense?"). Then step 1 is the player's statement and the glue only needs the SECOND step when the statement was not explicit. A generated ask is needed only when the commit sits on the top level (5.6 case C).
- "Naming the choice" = the judge maps the utterance to exactly one entry with a margin over the runner-up; a bare "yes / okay / do it" counts only when the parked entry was quoted back by the NPC in the previous line, or when it is the layer's only commit entry.
- **Ambiguous intent** (two entries fit): no click; NPC asks in character ("Speak plainly - is it to be Riften, or nothing?"). Never resolve ambiguity with list order.
- **STT** (`inputtext_s`): irreversible entries always get the read-back ("You mean to kill Kematu, then?") and execute on the second affirmative; a single recognised token never selects (REVIEW_40 item 13 kept). Typed input naming the choice explicitly may skip the read-back (config).
- CHIM's `confirmcommand` channel stays as the second net for entries the index marks META.
- **Timeouts**: never auto-pick, never auto-cancel (952 INFOs carry Walk Away flags, 904 name a walk-away topic - cancelling can have consequences). After N s of silence in a closed layer (default 45) the watchdog un-hides the vanilla menu with one notification. While a hidden session is open the player is in menu mode and cannot move, so the wait must be visible: HUD hint "{npc} is waiting for your answer".
- **Walking away mid-choice**: the only correct exit is the engine's cancel path (same as Tab): the engine then plays the walk-away topic / goodbye and scripts that depend on it still run. Triggers: the glue's leave hotkey, the judge's `leave` intent ("I need to think", goodbye) when the layer has no back-out entry, combat start. If a back-out entry exists, click that instead (it is the designers' intended exit). Whether key events reach Papyrus while the hidden menu is open is for the UI-path team (E16).
- **Scenes**: there is no scene player-dialogue action in Skyrim (section 0 item 9). A scene that wants an answer runs a ForceGreet package or waits on a blocking branch; the engine opens the Dialogue Menu itself -> same handler, closed layer from the first list. The "NPC is in a scene -> glue stands down" rule must therefore be: never OPEN a session on a scene actor, but DO handle a menu the engine opened (otherwise the vanilla menu would pop up in exactly the big set-piece moments). Also suppress CHIM chatter from the other scene actors during the wait (`_restrict_onscene` exists natively; chim-papyrus-plumbing.md:405).

### 6.5 Generic filler and ranking for the LLM
Biggest owners of top-level topics [V `json:toplevel_topics_by_quest`]: `ANDR_AJO_Quest` 332 (Andrealphus Jobs), `ACFDialogueWhiterun` 195, `WTDialogueIdle` 125, `ACFMTSRiftenDialogue` 123, `zzzCHGenericDialogue` 91, `ACFMTSWinterholdDialogue` 87, `DialogueWhiterun` 77, `DialogueRiften` 75 ... then real quests (`DarkBrotherhood` 66, `MQ201Party` 39, `MS01` 36, `MS11` 24, `MS08` 20, `MS09` 20).
Algorithm (server side, per list):
1. Closed layer -> send ALL entries (they are the conversation), hard cap 12, never bucket; order as the engine gave it.
2. Top-level list -> score each entry: +4 index says journal quest, +3 `topicIsNew`, +2 speech / priced / action tag, +2 service entry, +lexical similarity to the player's utterance (the DB already has `pg_trgm` - server-events-db.md:454), -3 owner quest is one of the filler quests above or a follower-framework command menu (Simple Follower Framework, Swiftly Order Squad: `[Manage with Swiftly Order Squad]`), -2 generic question shared by > 20 topics ("Who are you?", "What do you do here?").
3. Send the top 8 with stable ids `gen:idx`; the rest become one pseudo-entry `small talk (N more: rumours, local questions, follower commands)`. If the judge answers `small_talk`, a second cheap pass runs over the bucket only. Follower command trees are better left to CHIM's own follower actions unless the player clearly asks for the menu-only function.
4. Rumours (`RUMO` subtype, 12 player topics) and "What's the word?" style entries are selected only when the player explicitly asks for news; otherwise Grok's own chatter is richer and the real topic would replace it with a canned line.
UI-only fallback (no index hit): +3 `topicIsNew`, +2 tag, +lexical similarity, service regexes ("for sale", "rent a room", "training", "carriage|stop at|ferry").
