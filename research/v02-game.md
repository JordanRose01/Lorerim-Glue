**Lead ticks**: none while `leader=player`, `leader=auto`, auto mode on, or `wd=1` (PROTOCOL 1.4).
**Busy flag**: `setAnimationBusy(1, partner)` at start, on every scene change, every 5 s while the thread runs, and right before a lead request. Released in `ResetState` (end event, failed start, start timeout, game load). NEW safety net: if the thread is gone for 2.5 s and no `ostim_thread_end` arrived, `Tick` finishes the scene itself (`ev=end`, release, restore), so she can never stay locked.
**Redress at the end**: weapons + glue-removed clothes as v1; NEW for glue-started scenes (`bRedressAfter`, on): what both wore at the start (16 `GetWornForm`, once per scene) and is still off 4 s after the end is put back on, whatever OStim's own redress option says.
**Cold exemption**: `SurvivalModeImprovedApi.RestoreColdLevel(amount)` every 5 s while a thread runs or the glue holds the player's clothes. MCM: on/off + amount per 5 s (default 10, unknown right value - see open points).
**Snapshot v=2** keys in contract order before `class`: `x, loc, ltype, cellown, home, nhome, prent, nearf, bedown, sde`. Cost control: location name / type only when the Location form changes (<= 26 natives once); `cellown / home / nhome / sde` per NPC + cell + location, re-read after 120 s; `nearf / bedown` cached per cell, < 500 units moved, < 60 s (1 `FindFurniture` + <= 17 `GetFurnitureType`); `prent` only in inns, per cell per 120 s, and the reference loop runs AFTER the snapshot went out (a second snapshot follows only when the answer changed). **`lrg_scene`** new keys `auto, leader, stall, ncl, pcl, wd, nearf, undp` (before `tags`; `next` stays LAST); all of them are part of the de-duplication key. `nearf` is refreshed only at thread start and after a furniture change.

## Findings the integrator / other builders need (cross-file)
1. **Survival Mode Improved is ESL-flagged** (`SurvivalModeImproved.esp` header flag 0x200). PROTOCOL 4.3 names `Game.GetModByName(..) != 255`; that lookup only knows full plugins and would say "not installed". Used `Game.IsPluginInstalled("SurvivalModeImproved.esp")` (SKSE Game.psc:296) instead. PROTOCOL text should be corrected; no wire impact.
2. **`pullout` can never succeed with the installed packs.** Scan of all 607 installed scene files (OStim, OARE, Community Resource): the only `autoTransitions` ids are `climax` (6), `devour0` (3), `devour1` (1). So `do=pullout` always answers `Error: not possible in this position` (plus a notification). BEHAVIOUR should stop offering / resolving "pull out" (or map it to a goto the index picks); the game verb stays for packs that define it.
3. `bedown`: a bed reference without its own owner inherits the cell's ownership (the game's own rule), so `bedown` falls back to `cellown` instead of `none`.
4. `und` / `undp` are read from the real equipment at push time (4 `GetWornForm`), not tracked: they also see what OStim undresses by its own MCM rules. `und=1` = body slot empty. `undp` = `all` when nothing is worn on any of the four parts, else the parts that were on at scene start (or adoption) and are off now. A second push follows 3 s after a clothing command and 6 s after a start because equipment changes are not instant.
5. Partial undress refinement: for head / hands / feet, a slot whose item ALSO covers the body slot (robe with sleeves) is left out of the mask, in a scene and outside. The contract masks are the maximum. `RedressPartial` uses the full contract mask.
6. `leader=auto` is reported whenever `auto=1`, whoever switched it on; when auto mode ends the stored leader (or the MCM default) is reported again.
7. `ExtCmdLRG_SceneControl` from an NPC who is not the scene partner is refused with `a scene with someone else is running` (checked by actor, then by name). `stop` is exempt.
8. Watch / initiative: with initiative on, the watch lingers (no snapshots) up to 300 s after the NPC's last line while the player stays within 600 units, so an invitation can be followed through without staring at her. A new watch target gets >= 20 s before its first tick. The tick reuses a snapshot younger than 5 s instead of forcing a second witness scan; otherwise it forces one. Also skipped while the player is mounted.
9. Glue-removed clothes are now also put back at game load (v1 left a gap: the watch that would have re-dressed is reset by a load).
10. `CleanForWire` now also replaces `"` and newlines (PROTOCOL 0). `HandleCommand` answers `OStim is not installed` (closed list) instead of the old `OStim is not available`.
11. New MCM keys (all present in `config.json` + `settings.ini`, cross-checked by script: 27 used = 27 declared): `bNotifyErrors:General` 1 · `iDefaultLead:Intimacy` 0 (0 she leads, 1 I lead) · `bFurniture:Intimacy` 1 · `fFurnitureRadius:Intimacy` 1200 · `bRedressAfter:Intimacy` 1 · `bInitiative:Initiative` 1 · `fInitiativeInterval:Initiative` 90 (30..600) · `bColdExempt:Survival` 1 · `fColdRestore:Survival` 10. Explicitness labels are now Suggestive / Direct / Explicit and the help text says it covers flirting and invitations too (R5). For the owner notes: keys missing from an existing `MCM\Settings\LoreRimGlue.ini` fall back to these defaults; changed old keys do not.
12. Install: `install_mo2.ps1` as before (MO2 closed). No ESP / SEQ change, no Nemesis.
